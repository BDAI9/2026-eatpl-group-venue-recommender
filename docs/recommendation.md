# 추천 기준과 데이터 한계

> **핵심:** 취향을 하나의 평균값으로 단순화하지 않고, 식당은 **가장 많이 선택한 음식 종류**를 먼저 반영합니다. 알레르기 위험 제외는 순위보다 앞섭니다.

## 1. 후보 수집

1. 정해진 지역/역과 업종(식당·카페·술집)으로 K-Skill의 eat.pl 가맹점 후보를 조회합니다.
2. 잇플 업종·매장명으로 카테고리를 검증합니다. 지하철역은 좌표가 있는 매장에 대해 직선 반경 제한을 적용합니다.
3. 업종·상호에서 얻을 수 있는 음식 분류·가격대·알레르기 위험을 규칙 기반으로 추정합니다.
4. 설정에 따라 잇플 상세 메뉴·후기와 OpenRouter 정보를 뒤늦게 보강할 수 있습니다.

원본 후보가 제한되어 있거나 분류할 수 없으면 희망한 음식 종류가 누락될 수 있습니다. **추천 후보가 완전한 상권 목록이라는 의미는 아닙니다.**

## 2. 식당 추천 순서

```text
지역·업종 후보 조회
  → 알레르기 고위험 신호 제외
  → 선택한 음식 종류와 일치하는 후보
  → 음식 종류의 최다 득표를 먼저 비교
  → 같은 득표 수준에서 예산·분위기·맛집 유형 점수 비교
  → 동점이면 제공된 매출 순위로 정렬
```

예를 들어 중식 2명, 한식 1명인 경우 **안전 조건을 충족하고 중식으로 확인된 매장**이 한식 매장보다 먼저 추천됩니다. 이는 거대한 고정 가중치를 더하는 방식이 아니라, 음식 종류 득표를 우선 정렬 기준으로 두는 방식입니다. 여러 음식 종류로 분류되는 곳은 일치 종류 중 **최고 득표수만** 적용합니다.

**예외:** 중식 후보가 없거나 알레르기 고위험 신호로 제외되면 다른 선호 종류를 제시할 수 있으며, 이 경우 안내 문구를 표시합니다.

## 3. 세부 점수

음식 우선순위가 같은 식당 사이 또는 카페·술집의 일반 추천에서는 아래 신호를 조합합니다.

| 항목 | 적용 |
| --- | --- |
| 선호 음식·유형 일치 | 일치한 참여자 **1명당 +3**. 같은 사람은 중복 가산하지 않음 |
| 예산 적합 | 확인/추정 가격대가 개인 예산 안이면 **+2/명** |
| 예산 초과 | 가격대가 허용 구간을 크게 넘으면 **−2/명** |
| 분위기 일치 | **+1/명**. 근거가 약한 힌트는 반영치 감소 |
| 방문 특성 | 제공처가 명시적으로 `true`를 준 선호 신호만 **+2/명** |
| 알레르기 중간 위험 | **−2/해당 위험 신호**와 주의 표시 |
| 알레르기 높은 위험 | **추천 목록에서 제외** |
| 동점 정렬 | 실제 잇플 매출 순위값이 있는 곳을 기준으로 비교 |

※ 채식은 음식 분류와 별도 선호 옵션으로 보조 점수가 적용됩니다. 카페 디저트 선택은 메뉴 확인 정보를 활용한 별도 우선 조건이 있습니다. 정확한 산식은 `moim/recommend.py`의 `score_place`, `_cuisine_priority`, `recommend`가 기준입니다.

## 4. 데이터·AI의 역할

- **K-Skill / eat.pl:** 가게 후보·업종·주소·제공된 결제 순위 및 방문 특성.
- **업종 규칙:** 음식 종류, 알레르기 위험의 일부 신호, 기본 가격대 추정.
- **상세 정보 (선택):** 제공 가능한 메뉴·후기·편의 정보의 근거 보완.
- **OpenRouter (선택):** 추가 분류·가격대·분위기의 불확실한 추정. 반드시 필요한 핵심 랭커가 아닙니다.

AI 추정의 속도나 성공 여부와 무관하게 우선 제공 가능한 결과를 보여줄 수 있습니다. 화면이 배경 정보 갱신을 확인하더라도, 동일한 추천 결과를 통째로 다시 렌더링하지 않도록 설계했습니다.

## 5. 설명 가능한 한계

- **매출 순위 ≠ 사용자 적합도.** 매출 데이터는 점수 동률 시 보조 지표이지 보장된 만족도 점수가 아닙니다.
- **가격 추정 ≠ 실제 메뉴 가격.** 일부만 상세 메뉴 가격을 확인합니다.
- **영업시간 추정 ≠ 실제 운영시간.** 최근 결제 시각을 기반으로 추정한 시간은 매장 확인이 필요합니다.
- **알레르기 위험 낮음/미확인 ≠ 안전 보장.** 재료·교차접촉은 반드시 매장에서 확인해야 합니다.
- **투표의 우선순위는 정책적 선택.** 음식 종류가 더 중요한 현재 MVP 정책이며, 취향의 정량적 학습이나 사용자 만족도 검증을 완료했다는 뜻은 아닙니다.
