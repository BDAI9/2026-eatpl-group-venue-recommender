# GatherRank (지금어디가) · 제품 및 사용자 흐름

## 1. 문제 정의

여러 명이 모임 장소를 정할 때 메시지로 의견을 모으면 같은 질문이 반복됩니다. 구성원별 음식 종류·예산·분위기·알레르기 조건은 다르고, 최종 선택 기준도 명확하지 않습니다.

**목표:** 별도 계정 없이 링크 하나로 취향을 수집하고, 집계 결과와 추천 근거를 함께 보여 줍니다.

## 2. 이용 흐름

1. **지역:** 동네 또는 지하철역을 입력하고 중복 지역을 확인합니다.
2. **결정 방식:** 혼자 결정하거나, 함께 결정할 인원을 정합니다.
3. **장소 종류:** 카페·식당·술집과 먹고 싶은 종류를 선택합니다.
4. **추가 조건:** 이름(공동 모임), 예산·분위기·방문 특성·알레르기를 입력합니다.
5. **공유 모임방:** 링크를 공유하고, 각 구성원이 조건을 저장·수정합니다. 인원을 지정한 방은 인원이 찬 뒤 추천을 엽니다.
6. **추천:** 그룹 선호 집계와 장소별 일치 이유, 주의사항, eat.pl 상세 링크를 확인합니다.

혼자 결정할 경우 모임 공유 화면은 생략합니다. 참여자와 결과를 확인하는 화면은 자동 갱신되지만, 동일한 내용을 매번 통째로 다시 렌더링하지 않습니다.

## 3. 입력·출력

| 입력 | 출력에서 쓰는 방식 |
| --- | --- |
| 지역·역 | 잇플 후보 조회 및 역 기준 직선 반경 필터 |
| 카페/식당/술집 | 후보 유형 제한 |
| 음식 종류·메뉴 선호 | 투표 집계; **식당은 더 많이 선택한 종류를 우선 정렬** |
| 예산 | 확인 가능한 메뉴 가격 또는 업종 추정 가격대와 비교 |
| 분위기 | 상세 후기·편의 정보 또는 제한적인 추정 근거와 비교 |
| 동네/외국인/직장인 맛집 선호 | 제공처가 명시적으로 제공한 결제 특성에만 가점 |
| 알레르기 | 높은 위험 신호가 확인된 후보를 제외; 미확인은 경고 표시 |

## 4. 기능 범위

**구현:** 방 생성·초대·인원 제한·참여자 수정/삭제·방장 초기화, 선호 집계, 장소 추천, 카카오톡 공유/링크 복사, 선택적인 AI 정보 보강.

**구현하지 않은 항목:** 회원가입·인증 계정, 예약·결제, 여러 가게를 잇는 코스 추천, 알레르기 안전 보장, 실제 가격·운영시간 보장.

## 5. 주요 예외

- 동명 지역·불명확한 역: 지역 확인 또는 다시 선택
- 목표 인원 미달: 추천 버튼 대신 남은 참여 인원 안내
- 최다 선택 음식 후보 부재: 차선 후보와 사유 안내
- 위험도가 높은 알레르기 신호: 가게 제외
- 가격·알레르기 정보 미확인: 안전 또는 가격을 보장하지 않고 경고
- 외부 데이터/AI 오류: 확인 가능한 업종 근거로만 제한적으로 추천하거나 오류 안내

**주의:** 방 링크를 아는 사람은 참가자의 이름과 입력 조건을 볼 수 있습니다. 실사용 공개 전 접근·보관·삭제 정책의 추가 검토가 필요합니다.
