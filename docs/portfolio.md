# GatherRank · Group Preference-Aware Venue Recommendation

> 팀 전체의 구현을 설명한 문서입니다. 개인 GitHub/이력서에는 **자신이 실제 담당한 PR과 근거**만 골라 적으세요.

**사용자 서비스명:** 지금어디가 · **데이터:** K-Skill 경유 eat.pl/BC카드 · **추천:** 규칙 기반 그룹 선호 정렬

## 30초 소개

모임 장소를 정할 때 구성원마다 음식 취향·예산·알레르기 조건이 달라 합의가 어려운 문제를 해결하는 웹 서비스입니다. 링크 하나로 조건을 모으고, K-Skill을 통해 확보한 eat.pl 장소 후보에서 **다수 선호를 우선하는 설명 가능한 추천**을 제공합니다. AI는 불완전한 장소 정보 보강에 선택적으로 사용합니다.

## 기술과 설계

| 영역 | 구현 |
| --- | --- |
| 화면 | 모바일 HTML/CSS/JavaScript, Vercel |
| 백엔드 | Python API, Gunicorn, AWS Lightsail |
| 저장 | SQLite: 모임·참여자·추정 캐시 |
| 장소 데이터 | K-Skill / eat.pl·BC카드 결제 지표 |
| AI | 선택적인 OpenRouter 정보 보강 |
| 검증 | pytest, Playwright, GitHub Actions |

### 기술적으로 해결한 문제

- **조건 충돌:** 개인 선택을 모임 단위로 합산하고 가게별 일치 사유를 표시
- **추천 우선순위:** 중식 2표와 한식 1표라면 안전한 중식 후보를 먼저 제시하도록 랭커 개선
- **알레르기:** 확인 가능한 고위험 신호는 후보에서 제외하고 미확인은 경고
- **AI 대기:** 먼저 업종 규칙 결과를 제공하고 상세·AI 결과는 뒤에서 보강
- **화면 깜빡임:** 5/6·6/6의 동일 응답 재렌더링을 막고 변경 영역만 갱신
- **운영 안정성:** 백업·CORS·CI·프론트/백엔드 버전 확인 절차 마련
