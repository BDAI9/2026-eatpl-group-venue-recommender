# GatherRank — Group Preference-Aware Venue Recommendation

**지금어디가** · eat.pl/BC카드 데이터 기반 그룹 장소 추천 서비스

> **모임 참여자의 취향 투표를 집계하고, 장소 데이터의 근거와 안전 조건을 반영해 식당·카페·술집을 정렬하는 설명 가능한 추천 시스템.**

`Python` `SQLite` `JavaScript` `K-Skill / eat.pl` `Rule-Based Ranking` `Vercel` `AWS Lightsail`

누군가는 중식을, 다른 사람은 한식을 원하고 예산과 알레르기 조건도 다릅니다. GatherRank는 초대 링크로 개별 선호를 수집해 그룹 취향을 집계합니다. 식당은 음식 종류의 **최다 득표를 먼저 비교**하고, 같은 득표 수준에서 예산·분위기·방문 특성 등의 점수로 순위를 정합니다. 알레르기 고위험 신호가 확인된 후보는 제외합니다.

**이름 구분:** `GatherRank`는 프로젝트/기술 포트폴리오 이름이며, 실제 이용자가 보는 서비스명은 **지금어디가**로 유지합니다. 별도 머신러닝 모델을 학습한 프로젝트는 아니며, 외부 AI는 선택적인 장소 정보 보강에 사용합니다.

[서비스 체험하기](https://jj2ya.vercel.app/) · [사용 흐름](docs/product.md) · [시스템 구조](docs/architecture.md) · [추천 알고리즘](docs/recommendation.md)

> **데이터 안내:** 가게 후보와 결제 지표는 K-Skill 경유 eat.pl/BC카드 데이터를 활용합니다. 실제 메뉴·가격·영업시간·알레르기 안전 여부는 보장되지 않으며 매장에 확인해야 합니다. 로컬 `sample` 모드는 가상 데이터입니다.

## 해결하려는 문제

단톡방에서 장소를 정할 때 사람마다 원하는 음식·예산·분위기가 달라, 조건을 다시 묻고 투표하는 일이 반복됩니다. 지금어디가는 **개별 입력 → 조건 집계 → 근거가 있는 추천**을 한 흐름으로 묶습니다.

## 핵심 기능

| 기능 | 구현 내용 |
| --- | --- |
| 모임방 공유 | 별도 회원가입 없이 링크로 참여, 목표 인원 설정·응답 수정·방장 초기화 |
| 선호 수집 | 음식 종류, 1인 예산, 분위기, 방문 특성, 알레르기 |
| 그룹 집계 | 여러 사람의 선택 수를 비교하고 함께 볼 수 있도록 표시 |
| 장소 추천 | 식당은 **음식 종류 득표 우선** → 예산·분위기·방문 특성 점수 → 매출 순위 |
| 안전·근거 | 알레르기 고위험 후보 제외, 미확인 정보 경고, 실제 eat.pl 상세 링크 |
| 점진적 갱신 | 참여자·추천 상세 결과가 바뀐 경우 필요한 내용만 새로 반영 |

추천은 가게 목록과 분류 근거가 확보된 범위에서 이루어집니다. 최다 득표 음식이 없는 지역이거나 알레르기 위험으로 제외되면 차선 후보와 안내를 표시합니다.

## 사용자 흐름

`지역 선택 → 혼자/함께 결정 → 음식·업종 → 조건 입력 → 모임방 공유 → 장소 추천`

모임 인원을 지정한 경우 목표 인원이 참여하면 추천을 확인할 수 있습니다. 단독 선택은 공유 단계 없이 진행합니다.

## 로컬 실행

Python **3.10 이상**이 필요합니다. 애플리케이션 기본 서버는 표준 라이브러리로 실행됩니다.

```bash
cp .env.example .env
# .env에서 EATPL_SOURCE=sample 로 변경 (가상 데이터 테스트)
python -m moim
# 브라우저: http://127.0.0.1:8000/
```

```bash
python -m pip install pytest
python -m pytest -q
```

실제 데이터를 시험하려면 `EATPL_SOURCE=kskill`을 설정합니다. API 키는 코드에 넣지 말고 `.env` 또는 서버의 보호된 환경변수 파일에 저장하세요. Windows는 [별도 실행 안내](docs/windows-run.md)를 참고하세요.

## 프로젝트 범위와 주의사항

- 현재 주력 구현은 **한 장소 추천**입니다. 카페 → 식당 → 술집을 잇는 코스 추천은 포함하지 않습니다.
- 회원가입은 없고, 링크를 아는 사람은 모임 참여 조건을 볼 수 있습니다. 실사용 전 개인정보·보관 정책 검토가 필요합니다.
- AI는 일부 정보의 **추정·보강** 역할입니다. 가격·분위기·운영시간·알레르기 안전성을 확정하지 않습니다.
- **GitHub 병합과 AWS 반영은 별개**입니다. 운영 백엔드의 정확한 배포 커밋은 서버에서 별도로 확인해야 합니다.
- `taste-demo/`는 실제 서비스가 아닌 [과거 Streamlit 시제품](taste-demo/README.md)입니다. `odiga_v1.pdf`는 저장소에 남아 있는 별도 PDF 파일이며, 현재 실행 코드가 아닙니다.
