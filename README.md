# 2026 Project Demo — 함께 고르는 모임 장소

모임을 만들고 **링크를 공유**하면, 참여자들이 각자 선호와 알레르기를 체크하고 그걸 합쳐 **카페·식당·술집**을 추천합니다. 추천된 가게를 누르면 **잇플 상세 페이지**로 이동합니다. (When2meet처럼 링크 하나로 모이는 방식)

## 사용 흐름

1. 첫 화면에서 지역과 혼자·다같이 선택 후 장소와 조건을 고릅니다.
2. 조건을 저장하면 모임이 만들어지고 공유 링크가 생깁니다. 링크를 받은 사람도 각자 체크합니다.
   다같이 고를 때 인원을 지정하면 실제 응답이 그 인원에 도달한 이후에는 추가 참여를 막습니다. 기존 방이나 인원을 지정하지 않은 방은 최대 30명입니다.
   - **지역** (홍대, 성수 … 또는 직접 입력)
   - **카페 / 식당 / 술집** 중 하나 → 고른 것에 맞춰 다음 선택지가 바뀝니다
     - 카페: 커피 맛집, 디저트-케이크, 베이커리, 아이스크림 빙수
     - 식당: 한식, 중식, 일식, 양식, 아시안, 기타외국식, 고기-구이, 분식, 치킨버거피자. 채식은 별도 선호 옵션
     - 술집: 호프·맥주, 이자카야, 와인·칵테일 바 …
   - **1인 예산**, **분위기**(최대 3개), **알레르기**(+ 기타 직접 입력)
   - **방문 특성 선호**: 동네 주민·외국인·직장인 방문 신호를 우선 반영합니다. 필수 조건이나 방문을 보장하는 정보는 아닙니다.
3. **모두의 선택**에서 투표 현황을 실시간(5초마다)으로 봅니다.
4. **추천 받기** → 가장 많이 고른 지역·장소로 추천합니다 (직접 바꿀 수 있음).
   - 누구 하나라도 가진 **알레르기 위험이 높은 업종은 제외**합니다.
   - **종류·예산·분위기**는 같은 걸 고른 사람이 많은 가게일수록 위로 올라갑니다.
   - 가게를 누르면 잇플로 이동합니다.

## 실행

[Windows에서 ZIP 실행 및 .env 설정](docs/windows-run.md)

Python 3.10 이상, 추가 설치 없음 (표준 라이브러리만 사용).

```bash
python -m moim          # 이 컴퓨터에서만: http://127.0.0.1:8000/
python -m moim --lan    # 같은 와이파이의 친구들도 접속 (터미널에 주소가 표시됨)
python -m pytest -q     # 테스트 (pytest 필요)
```

Windows에서 `--lan`으로 처음 실행하면 방화벽 허용 창이 뜰 수 있어요. '개인 네트워크'를 허용하세요.

## 설정 (`.env`)

`.env.example`을 `.env`로 복사해 필요한 값을 입력합니다. `.env`는 Git에 올리지 않습니다. 서버 설정은 별개이므로 로컬 파일은 서버에 자동 반영되지 않습니다.

| 변수 | 설명 |
| --- | --- |
| `EATPL_SOURCE` | `kskill`: 실제 잇플 장소. `sample`: 로컬 테스트용 가상 장소 |
| `OPENROUTER_API_KEY` | AI 추정에 사용. 비우면 업종 정보로만 추천 |
| `OPENROUTER_MODEL` | 쉼표로 무료 모델을 지정. 비우면 기본 무료 모델을 순서대로 시도 |
| `EATPL_DETAIL_ENABLED` | `1`: 잇플 상세 메뉴·편의 정보와 후기 요약을 조회 |
| `KAKAO_JS_KEY` | 카카오톡 공유에 사용하는 팀 앱 JavaScript 키 |
| `KAKAO_REST_API_KEY` | 선택. 동명 지역 대조에 쓰는 서버용 키 |

기본 로컬 실행은 샘플 모드이며 화면에 가상 데이터임이 표시됩니다. 실제 장소를 검색하려면 `EATPL_SOURCE=kskill`을 설정하세요. 공개 서버는 가상 데이터의 혼동을 막기 위해 K-Skill만 허용합니다. 예전 `.env`의 `auto`는 로컬 샘플 모드로만 처리하며, `direct` 설정은 더 이상 지원하지 않습니다.

### K-Skill 잇플 검색

- 검색 지역과 업종이 K-Skill 프록시 운영자에게 전달됩니다. 반환된 잇플 상세 주소를 검증해 변경 없이 브라우저에서 엽니다.
- 잇플 검색 응답에는 가격·메뉴·재료·분위기 정보가 없습니다. 상세 조회를 켜면 제공되는 메뉴·가격·편의 안내를 반영하고, 선택적으로 OpenRouter가 메뉴와 후기 요약의 근거를 해석합니다.
- 잇플은 주소로 가게 후보를 조회합니다. 지하철역을 입력하면 K-Skill 카카오맵 검색에서 정확한 역을 확인하고, 앱이 가게 좌표로 직선 반경 500m 이내를 거릅니다. 잇플 조회 한도와 좌표 제공 여부에 따라 일부 가게는 표시되지 않을 수 있습니다.
- 전국·지역 매출 순위와 방문 특성은 제공된 실제 값이 있을 때만 표시합니다. 운영 예상 시간은 최근 한 달 결제 승인 시각 기반의 추정이므로 매장에 확인해야 합니다.
- [공모전 안내](https://edu.bccard.ai/static/contest/apply.html)와 [K-Skill 안내](https://github.com/NomaDamas/k-skill/blob/main/bccard-eatpl-search/instruction.md)를 확인하고 공개 운영 및 데이터 사용 조건을 제공처에 확인합니다.

### AI 추정의 한계
- 가격대·분위기는 가게 이름과 업종에 기반한 **추정값**이라 틀릴 수 있고, 화면에 표시됩니다.
- 알레르기는 로컬 업종·상호 규칙으로 확인할 수 있는 위험 신호만 반영합니다. 실제 재료를 알 수 없으므로 안전을 보장하지 않으며, 반드시 매장에 직접 확인해야 합니다. 참여자의 알레르기 목록은 AI에 보내지 않습니다.
- 무료 모델은 하루 요청 수 제한이 있고 붐비면 다음 모델로 넘어갑니다. 모두 실패하면 업종 정보로만 추천합니다. 같은 가게의 추정은 저장해 두고 다시 쓰기 때문에 요청 수가 줄어듭니다.
- 추천 한 번에 AI로 보내는 가게는 **점수가 높은 상위 12곳**(요청 1번)뿐입니다. 규칙상 이미 제외된 가게는 보내지 않습니다.
- 무료 모델은 응답에 40~70초가 걸려서, **업종 정보로 결과를 먼저 보여 주고** AI 추정은 뒤에서 돌립니다. 화면이 6초마다 다시 물어 AI가 끝나면 결과가 자동으로 바뀝니다. AI가 실패하면 5분 동안은 다시 부르지 않습니다.
- 알레르기 위험 신호에는 업종별 대표 메뉴 규칙(예: 호프 → 밀 높음, 이자카야 → 대두·밀 보통)과 이름 속 재료 규칙(예: 새우·우동·치즈 → 높음)을 함께 씁니다.

### 진단 (실제 환경 확인)

```bash
python -m moim.diagnose             # OpenRouter·잇플·추천을 실제로 호출해 확인
python -m moim.diagnose --no-eatpl  # 잇플을 호출하지 않고 샘플로 시험
```

모델별 응답 여부·속도·추정 내용, 잇플 검색 결과(건수·업종 분포·상세 링크·순위값), 예시 모임 3개의 추천 결과를 `diagnose_report.md`/`.json`에 남깁니다. 키는 보고서에 쓰지 않습니다.

2026-11-17 실측(샘플 가게, OpenRouter만): gemma 두 모델은 상류 한도로 429, `nvidia/nemotron-3.5-lightning:free`가 응답(40~70초). 첫 화면 0.03초 이내, AI 반영까지 약 1분. K-Skill 경로로 실제 잇플 장소를 조회했습니다.

## 코드 구조

| 경로 | 내용 |
| --- | --- |
| `moim/options.py` | 선택지 목록과 입력 검증 |
| `moim/store.py` | SQLite: 모임방, 참여자, AI 추정 캐시 |
| `moim/eatpl.py` | K-Skill 잇플 검색, 데이터 검증, 로컬 샘플 |
| `moim/estimate.py` | 업종 규칙 + OpenRouter AI 추정 |
| `moim/recommend.py` | 투표 집계, 알레르기 제외, 선호 점수 |
| `moim/server.py` | HTTP 서버와 API |
| `moim/diagnose.py` | 실제 환경 진단 스크립트 |
| `web/` | 화면 (모임 만들기, 모임방) |
| `tests/test_moim.py` | 테스트 (잇플·OpenRouter는 가짜 서버로) |

## 아직 안 되는 것
- [테스트 서버](https://jj-moim.amazonlightsail.com/)는 수동 배포 중입니다. 정식 운영 전 보안·개인정보 보호와 공모전 유입 집계 검증이 남아 있습니다.
- 로그인: 이름만으로 참여합니다. 링크를 아는 사람은 누구나 참여할 수 있습니다.
- 여러 곳을 잇는 코스(카페 → 식당 → 술집)는 이번 버전에서 뺐습니다.

## 협업 흐름

1. 작업 브랜치에서 변경 → PR의 **base는 `dev`**
2. 팀원이 확인 후 `dev`에 병합 → 통합 테스트 후 `dev`에서 `main`으로 PR
3. API 키나 개인 비밀값은 저장소에 올리지 않습니다.
